# AI assistance log

I built this with Claude Code (Claude Opus) as a pair programmer. This log records, as they happened, the wrong assumptions, bugs and bad outputs, and how each was fixed. It records what went wrong, not what went well.

| # | Stage | What went wrong / wrong assumption | How it was caught | Fix |
|---|-------|-------------------------------------|-------------------|-----|
| 1 | Setup | The original plan assumed Docker, Python and Git were installed. None were, and Docker Desktop needs WSL2 plus a reboot. | Checked the tooling before writing any code. | I switched to n8n Cloud and installed Python, Git and Node with winget. On Cloud, `$env`, the local filesystem and the n8n CLI aren't available, so secrets moved to an n8n credential, persistence moved to Webhook.site plus the webhook response, and import moved to the UI. |
| 2 | Setup | Reading the brief .docx failed ("file is being used by another process") because it was open in Word. | Error on read. | Opened it with shared-read access instead. |
| 3 | Setup | After the winget install, `node`/`git` weren't found in the same shell. | Command not found. | PATH is only picked up by new shells, so I refreshed it from the registry. |
| 4 | Rules design | The first keyword list for `security_signal` included `login`, `logging in` and `sso`. Combined with "raise priority to High", that would have made message #4 (a how-to question about SSO) High priority. | Tracing message #4 through the rules by hand before writing tests. | Narrowed the list to access *failures* only (401/403, "can't log in", "locked out"...). Unit test `#4 SSO question` pins this. |
| 5 | Rules design | The first `outage_language` list included bare `everyone` and `all users`. Feature requests use those words too ("everyone on my team wants..."), so they would have been escalated as outages. | Review of false-positive risk. | Removed them. Kept multi-word phrases only, matched on word boundaries. |
| 6 | Rules design | The spec I started from said to escalate billing when "either the invoiced amount or the discrepancy exceeds $500". That collapses to "invoiced amount > $500", because the discrepancy can never be larger than the largest amount. The "either" option added nothing. | Writing the threshold code. | Renamed the option to `any_amount` (chosen) vs `discrepancy`. Both are unit-tested. Amounts are parsed from the raw text by regex, not taken from the LLM, so a hallucinated number can't trigger escalation. |
| 7 | n8n glue | I nearly used `$json` inside Code nodes. In n8n's default "Run Once for All Items" mode `$json` isn't defined; `$input.first().json` is. | Design review. `tests/workflow_smoke.test.js` now runs the generated Code nodes with only `$input`/`$()` available, so this class of bug fails the test. | Used `$input.first().json` and `$('Node').first().json` throughout. |
| 8 | Git | Git had no user identity configured on this machine. | `git config user.email` returned nothing. | Set a repo-local identity only. Didn't touch global config. |
