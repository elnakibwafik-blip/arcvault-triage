# AI assistance log

I built this with Claude Code (Claude Opus) as a pair programmer. This log records, as they happened, the wrong assumptions, bugs and bad outputs, and how each was fixed. It records what went wrong, not what went well.

| # | Stage | What went wrong / wrong assumption | How it was caught | Fix |
|---|-------|-------------------------------------|-------------------|-----|
| 1 | Setup | The original plan assumed Docker, Python and Git were installed. None were, and Docker Desktop needs WSL2 plus a reboot. | Checked the tooling before writing any code. | I switched to n8n Cloud and installed Python, Git and Node with winget. On Cloud, `$env`, the local filesystem and the n8n CLI aren't available, so secrets moved to an n8n credential, persistence moved to Webhook.site plus the webhook response, and import moved to the UI. |
| 2 | Setup | Reading the brief .docx failed ("file is being used by another process") because it was open in Word. | Error on read. | Opened it with shared-read access instead. |
| 3 | Setup | After the winget install, `node`/`git` weren't found in the same shell. | Command not found. | PATH is only picked up by new shells, so I refreshed it from the registry. |
| 4 | Rules design | The first keyword list for `security_signal` included `login`, `logging in` and `sso`. Combined with "raise priority to High", that would have made message #4 (a how-to question about SSO) High priority. | Tracing message #4 through the rules by hand before writing tests. | Narrowed the list to access *failures* only (401/403, "can't log in", "locked out"...). Unit test `#4 SSO question` pins this. |
| 5 | Rules design | The first `outage_language` list included bare `everyone` and `all users`. Feature requests use those words too ("everyone on my team wants..."), so they would have been escalated as outages. | Review of false-positive risk. | Removed them. Kept multi-word phrases only, matched on word boundaries. |
| 6 | Rules design | The spec I started from said to escalate billing when "either the invoiced amount or the discrepancy exceeds $500". That collapses to "invoiced amount > $500", because the discrepancy can never be larger than the largest amount. The "either" option added nothing. | Writing the threshold code. | Renamed the option to `any_amount` (chosen) vs `discrepancy`. Both are unit-tested. Amounts are parsed from the raw text by regex, not taken from the LLM, so a hallucinated number can't trigger escalation. |
| 7 | n8n glue | I nearly used `$json` inside Code nodes. In n8n's default "Run Once for All Items" mode `$json` isn't defined; `$input.first().json` is. | Design review. `tests/workflow_smoke.test.js` now runs the generated Code nodes with only `$input`/`$()` available, so this class of bug fails the test. | Used `$input.first().json` and `$('Node').first().json` throughout. |
| 9 | LLM | I had checked Groq's model docs and they still listed `llama-3.3-70b-versatile`, so I set it as the default. On a free-tier key the API returned `404 model_not_found`. | First live call. | Listed the models via `/openai/v1/models` and switched to `openai/gpt-oss-120b` (reasoning model, `reasoning_effort: low`). The model name lives only in `config/rules.json`. Lesson: check model availability with the actual key, not the docs page. |
| 10 | LLM | I assumed the free tier had enough throughput. `gpt-oss-120b` is capped at **8,000 tokens/minute**, and one message (3 calls, ~2k tokens each) nearly uses all of it, so back-to-back test calls hit 429. | 429 responses during prompt testing. | `check_groq.py` now waits for the "try again in Xs" time. `send_samples.py`/`eval.py` pace messages. This is also a production-scale point in the write-up: shorter prompts, a smaller model for classification, paid tier. |
| 11 | Prompts | v1 classification reported confidence 0.92 on a three-intent message, despite the calibration guide. | Edge case E1. | Added `secondary_categories` plus a deterministic `multi_intent` escalation rule. See CHANGELOG_PROMPTS.md. |
| 12 | Prompts | Angry $45 billing complaint gets High priority, even after v2 said "never by tone". | Edge case E5, before and after v2. | Not fixed; documented as a known disagreement. It doesn't change routing. |
| 13 | n8n setup | The first `N8N_WEBHOOK_URL` was the Webhook node's **test** URL (`/webhook-test/...`), which returns 404 unless "Execute workflow" was just clicked. | First live POST returned 404 with n8n's hint. | Switched to the production URL (`/webhook/...`); the workflow must be Activated. The README calls this out. |
| 14 | Tooling | I used a PowerShell `Get-Content`/`Set-Content` one-liner to change a default value. Windows PowerShell 5.1 read the UTF-8 file as ANSI, so an en dash in `eval.py` turned into `â€“`, and a BOM was added. | The editor's diff of the change showed the mojibake. | Replaced the character, rewrote both files as UTF-8 without BOM, and checked them for non-ASCII bytes. After that I only edited files with the editor tool, not shell text replacement. |
| 15 | Git | My pre-commit "no Groq key" check used invalid `git grep` argument order. It errored, and the PowerShell `if` read the error as "no match", so the commit went ahead without a real check. | Read the command output after the commit. | Re-ran it correctly against `HEAD` (0 hits, `.env` not tracked). The same key check is also built into `build_workflow.py`, which refuses to write the workflow if it finds a key. |
| 16 | n8n setup | My import instructions said "create a Header Auth credential". In the n8n Cloud UI the imported nodes didn't show a credential dropdown where the instructions said it would, and the Enrich node was left without a credential. Real messages then returned `200` with an empty body, and later `Credentials not found` on enrichment. | Live test: the empty-message path (1 LLM call) worked, the full path didn't. I split the test by path to narrow it down, then read the error the workflow had recorded in `llm_errors`. | Switched the generator and README to the built-in **Bearer Auth** credential type, which is what the user found and set up in the UI. The `Credentials not found` run is a good demonstration of the failure path: the record was escalated as `llm_failure` with the reason, not dropped. |
| 17 | Testing | My ad-hoc PowerShell test command put `$1,240` inside a double-quoted string, so PowerShell interpolated `$1`/`$980` and the workflow received `\,240`. | The returned `raw_message` looked wrong. | Not a pipeline bug. The real scripts send text from `tests/golden.json`, so they aren't affected. I only used the scripts after that. |
| 18 | Instructions | I gave the user a `curl.exe -d "{\"source\":...}"` command to run by hand. That escaping works in cmd and bash, but Windows PowerShell 5.1 strips the `\"` when calling native executables, so curl got broken JSON (n8n returned 422) and treated the leftover words as hostnames. | The user pasted the error output. | Gave an `Invoke-RestMethod` version instead, and added `send_samples.py --message "..." --source ...` so there's nothing to quote by hand. The README notes the pitfall. |
| 19 | Prompts | The v2 prompt changes (aimed at E1, E5 and S1) raised confidence on the vague message E2 "it's broken again" from 0.62 (v1) to 0.78, so it no longer escalates and goes straight to engineering. I didn't re-test E2 after v2, only the cases I had changed. | Full eval run (`output/eval_report.md`). | Recorded as a failing case. Lesson: after any prompt change, re-run the whole eval set, not just the cases the change targeted. |
| 20 | Rules | The `security_signal` detail string always said "priority raised to High", even when the LLM had already returned High and nothing changed (sample #1). The structured field `priority_adjusted_by` was correct (`null`); only the text was wrong. The unit test only covered the case where the priority does get raised. | Reviewing the rendered screenshot of sample #1. | The detail now says "already High, no change" or "raised from X to High". Added a unit test for the already-High case. workflow_version 1.0.1; redeployed and re-ran the samples. |
| 8 | Git | Git had no user identity configured on this machine. | `git config user.email` returned nothing. | Set a repo-local identity only. Didn't touch global config. |
